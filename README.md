# NEST

---

## Техническая архитектура и статус реализации

NEST разрабатывается как **модульный монолит** с использованием принципов **Clean Architecture**.

Основное разделение проекта:

```text
Domain → Application → Infrastructure → API
```

### 1. Архитектурный стек

**Реализовано:**

* [x] **Clean Architecture** - разделение ответственности между Domain, Application, Infrastructure и API.
* [x] **CQRS (`MediatR`)** - разделение операций изменения и получения данных на Commands и Queries.
* [x] **Entity Framework Core & PostgreSQL** - работа с реляционной базой данных, миграциями, связями и ограничениями.
* [x] **Docker & Docker Compose** - запуск PostgreSQL в изолированном окружении для локальной разработки.
* [x] **FluentValidation** - валидация входных данных перед выполнением команд.
* [x] **Swagger** - документирование и тестирование REST API.
* [x] **Централизованная обработка ошибок** - middleware для обработки ошибок валидации и ошибок базы данных.

**В процессе внедрения:**

* [ ] **Authentication & Authorization** - система аутентификации и авторизации на базе JWT и ASP.NET Core Identity.
* [ ] **RabbitMQ** - асинхронное взаимодействие между модулями и возможными будущими сервисами.
* [ ] **MinIO (S3 API)** - объектное хранилище для файлов и вложений.
* [ ] **Angular & TypeScript** - клиентская часть приложения и интеграция с REST API.
* [ ] **Unit & Integration Tests** - автоматическое тестирование Domain, Application и API.

---

### 2. Статус продуктовых модулей

* [x] **Users** - создание, получение, изменение и удаление пользователей.
* [x] **Boards** - создание, получение, изменение и удаление Kanban-досок.
* [x] **Columns** - создание, получение, изменение и удаление колонок, автоматическое определение позиции и обработка задач при удалении.
* [x] **Tasks** - задачи с приоритетами, дедлайнами, статусом выполнения, контекстами и позиционированием внутри колонок.
* [ ] **Comments (В разработке)** - комментарии к задачам.
* [ ] **Attachments (Планируется)** - файлы, прикреплённые к задачам и комментариям.
* [ ] **Dashboard (Планируется)** - главная страница с последними изменениями и настраиваемыми виджетами.
* [ ] **Notes (Планируется)** - текстовые заметки и хранение документов.
* [ ] **Recipes (Планируется)** - база рецептов и работа с ингредиентами.
* [ ] **Finance (Планируется)** - учёт расходов и доходов, статистика и накопления.
* [ ] **Settings (Планируется)** - профиль пользователя, настройки интерфейса, языка и темы.

## О проекте

**NEST** - личное приложение для хранения заметок, управления задачами, рецептов и учёта финансов в одном месте.

Я разрабатываю его как **pet-project**, чтобы на практике углубиться в **C#, ASP.NET Core, Entity Framework Core и Angular**, а также разобраться с **DDD, CQRS, Clean Architecture и проектированием модульного монолита**.

Главная цель проекта - не просто получить работающее приложение, а разобраться, **почему архитектура устроена именно так и какие задачи решает каждый из используемых подходов**.

---

## Что будет в NEST

Основные направления приложения:

* **Dashboard** - главная страница с последними изменениями и настраиваемыми блоками.
* **Notes** - заметки и документы.
* **Tasks** - Kanban-доски с задачами, комментариями и файлами.
* **Recipes** - рецепты и ингредиенты.

# Tasks

Основной рабочий модуль NEST - Kanban-доски с динамическими колонками и задачами.

Например:

```text
TODO → В процессе → Review → Done
```

Пользователь сможет самостоятельно создавать и настраивать колонки.

### Основные возможности

* создание и редактирование досок;
* создание и редактирование колонок;
* изменение порядка колонок;
* создание и редактирование задач;
* изменение порядка задач внутри колонок;
* перенос задач между колонками;
* Drag & Drop;
* приоритеты и дедлайны;
* отметка выполнения задач;
* комментарии;
* вложения;
* удаление и архивирование;
* копирование задач между досками.

При удалении колонки пользователь сможет выбрать, что делать с находящимися внутри задачами: удалить их вместе с колонкой или перенести в другую колонку.

На текущем этапе NEST представляет собой **модульный монолит**.

Основные функциональные модули:

```text
NEST
├── Users
├── Tasks
├── Notes
├── Recipes
├── Finance
└── Dashboard
```

Проект постепенно развивается от базовой функциональности к более сложным возможностям.

Для проектирования используются:

* **Clean Architecture**
* **DDD**
* **SOLID**
* **CQRS**

В дальнейшем отдельные функциональные модули при необходимости можно будет выделить в самостоятельные сервисы. На текущем этапе основной целью является построение хорошо разделённого модульного монолита.

# CQRS

В проекте операции изменения и получения данных разделены на **Commands** и **Queries**.

### Commands

```text
CreateTask
UpdateTask
MoveTask
DeleteTask

CreateBoard
UpdateBoard
DeleteBoard

CreateColumn
UpdateColumn
DeleteColumn

CreateComment
```

### Queries

```text
GetTask
GetTasks
GetBoard
GetBoards
GetColumn
GetColumns
UpdateComment
DeleteComment
```

Общий принцип обработки запроса:

```text
HTTP Request
     ↓
Controller
     ↓
Command / Query
     ↓
MediatR Handler
     ↓
Application
     ↓
Infrastructure / Database
```

Например, создание задачи:

```text
POST /api/tasks
     ↓
CreateTaskCommand
     ↓
CreateTaskCommandHandler
     ↓
Entity Framework Core
     ↓
PostgreSQL
```

Получение задачи:

```text
GET /api/tasks/{id}
     ↓
GetTaskQuery
     ↓
GetTaskQueryHandler
     ↓
Entity Framework Core
     ↓
PostgreSQL
```

# Хранение файлов

Файлы задач и комментариев не планируется хранить непосредственно в PostgreSQL.

В базе данных будут храниться их метаданные:

```text
FileName
ContentType
Size
StorageKey
```

Сами файлы будут размещаться во внешнем Object Storage.

Для локальной разработки планируется использовать **MinIO** с S3 API.

# RabbitMQ

RabbitMQ планируется использовать для асинхронного взаимодействия между отдельными модулями и возможными будущими сервисами.

Например:

```text
Task Completed
      ↓
Domain Event
      ↓
RabbitMQ
      ↓
Другой модуль
```

При этом RabbitMQ не планируется использовать там, где обычное синхронное взаимодействие является более простым и подходящим решением.

# Цель проекта

NEST - это не просто приложение с заметками, задачами и финансовым учётом.

Главная цель проекта - **на практике разобраться в разработке backend-приложений на C#/.NET и научиться осознанно проектировать его архитектуру**.

Мне важно понимать не только **как написать код**, но и **почему решение устроено именно так**, какие проблемы оно решает и какие компромиссы с ним связаны.
